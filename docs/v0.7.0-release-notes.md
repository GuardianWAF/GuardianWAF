# GuardianWAF v0.7.0

**Release date:** 2026-11-08. `VERSION`, image tags and the Helm chart version
are 0.7.0 ([release checklist](release-checklist.md)).

0.7.0 is a hardening and simplification release: two product areas were removed,
Raft gained snapshots and log compaction, and detection and the request path were
tightened against measured bypasses and false positives. Changes below are the
v0.6.0 → main range (about 360 commits; 192 are fixes).

## Breaking changes

- **Compliance reporting removed** (`eb3c8fa`). The `compliance` config section
  is rejected at load.
- **Tenant billing plans and invoices removed** (`14d50fa`). Tenant isolation,
  per-tenant WAF config and rules remain. The billing config keys are rejected at
  load.
- **`website/` removed** (`60ff8bc`). The marketing site no longer lives in this
  repository, and its CI job and Dependabot entry are gone.

Remove the rejected sections from your YAML before upgrading; see
[removed sections](configuration.md#removed-sections).

## Highlights

**Cluster**
- Raft state-machine snapshots, log compaction and InstallSnapshot for lagging
  followers; compaction is on by default (`cluster.snapshot_threshold`, 10000).
- Deterministic ban expiry fixed at proposal time, so replay cannot resurrect
  expired bans.
- Unset election and heartbeat timings are normalized (zero timings caused an
  election storm).
- StatefulSet pods drain before shutdown; the cluster manifest image tag is fixed.

**Request path**
- Bodies the WAF cannot decode are blocked with 400 instead of being forwarded
  on raw-byte inspection; decoded expansion is capped (413).
- `X-Forwarded-For` walking stops at entries it cannot parse; upstreams get the
  client chain and scheme only from trusted proxies.
- Concurrent inspection of bodies over 256 KiB is bounded (503 when saturated).

**Admin surface**
- API key rotation revokes sessions; failed key attempts share the login lockout.
- Hash-chained dashboard audit log with `guardianwaf verify-audit`.
- Tenant-scoped keys see only their tenant's `/api/v1/stats`.

**Detection** (each fix pinned by a regression test; see
[detection quality](detection-quality.md))
- New detectors, on by default: `crlf` (HTTP response splitting, header
  injection, SMTP/IMAP command and mail-header injection) and `ldapi` (LDAP
  filter injection); `ssti` now also flags Server Side Includes directives
  (`<!--#exec -->`). Found by running GoTestWAF, see
  [results](gotestwaf-results.md). Existing configs pick them up without edits;
  turn one off with `waf.detection.detectors.<name>.enabled: false`.
- Base64 values that decode to text are scanned as that text (query, form,
  multipart, JSON, cookies, headers, path), and a query string or form body is
  read across its parameters when a raw `&` starts an HTML entity. Turn the
  first off with `waf.sanitizer.decode_base64: false`.
- Gaps found by GoTestWAF are closed ([results](gotestwaf-results.md),
  [rules](detection-quality.md#coverage-added-after-the-gotestwaf-run)): XSS
  sinks reached through `call`/`apply`/optional chaining, NoSQL and prototype
  pollution payloads, `$IFS` shell tricks and deserialization tags, overlong
  UTF-8 and UNC paths, system-catalog SQL, Log4Shell and out-of-band callback
  domains, UTF-7 and schema-fetch XML, more scanner `User-Agent`s. GoTestWAF
  went from 42.9% to 100% of attacks blocked; the fixes were made against that
  suite, so re-measure before quoting the number.
- Bypasses closed: urlencoded form bodies, JSON bodies, URL-encoded cookies,
  application-defined headers, home-directory secret files, JavaScript string
  breakouts.
- False positives removed: binary uploads and multipart forms, SQL keywords and
  Windows paths in prose, same-site absolute redirects, and server-side JS
  operator names (`$where`) mentioned in prose.
- Large-body inspection is 1.3-2.8x faster.

**Observability**
- OTLP/HTTP JSON trace exporter and W3C trace-context propagation.

**Library mode**
- Layers are built through the standalone registry, so library mode runs the same
  11 detectors, API security and per-path body limits.

## Toolchain and supply chain

- Docker and CI images build with Go 1.27.3; CI tests Go 1.26.10 and 1.27.3.
  `go.mod` still declares 1.26.10 as the minimum.
- Playwright image, trufflehog and GitHub Actions are pinned by digest or SHA.

## Upgrading

1. Remove the `compliance` and tenant billing sections from your config, then run
   `guardianwaf validate`.
2. Run in monitor mode first and compare against your baseline; detection
   scoring changed in both directions.
3. If you run Raft, upgrade one node at a time and confirm each rejoins before
   the next ([clustering](clustering.md)).

## Known limits

See [production readiness](production-readiness.md): detection numbers come from
in-repo corpora, the Raft wall-clock soak and large-body p99 have not been
measured on release hardware, and no independent security review has been done.
