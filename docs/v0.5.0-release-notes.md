## New Detectors

### HTTP Request Smuggling (`smuggling-detector`)

Inspects HTTP framing headers for desync attacks where a front-end proxy and back-end server disagree on request boundaries. These attacks bypass WAF inspection entirely — the malicious payload lives in a "second" request the back-end sees but the WAF doesn't.

**6 vectors detected:**

| Vector | Pattern | Severity |
|---|---|---:|
| CL.TE conflict | Both `Content-Length` and `Transfer-Encoding: chunked` | Critical |
| CL.CL conflict | Duplicate `Content-Length` with different values | Critical |
| TE.TE obfuscation | `Transfer-Encoding` not exactly `chunked` (case/space/value tricks) | Critical |
| Duplicate TE | Multiple `Transfer-Encoding` headers | Critical |
| HTTP/1.0 + TE | Transfer-Encoding on HTTP/1.0 (non-standard framing) | High |
| Header injection | CR/LF/null bytes in CL or TE header values | Critical |

Tests: 15 unit cases + `FuzzSmugglingDetector` (14.7M fuzz executions, 0 crashes).

### Open Redirect (`openredirect-detector`)

Inspects redirect-type parameters and headers for untrusted external URLs that enable phishing via open-redirect vulnerabilities.

**18 redirect parameter names:** `redirect`, `redirect_uri`, `redirect_url`, `return`, `return_url`, `returnurl`, `returnTo`, `return_to`, `next`, `callback`, `callback_url`, `target`, `goto`, `dest`, `destination`, `continue`, `redir`, `r`.

**6 redirect headers:** `Location`, `Refresh`, `X-Redirect`, `X-Forwarded-Host`, `Referer`, `Origin`.

| Vector | Example | Severity |
|---|---|---:|
| External URL | `?redirect=https://evil.com` | High |
| Protocol-relative | `?redirect=//evil.com` | High |
| Scheme injection | `?redirect=javascript:alert(1)` | Critical |
| Data exfil | `?redirect=data:text/html,...` | Critical |
| Backslash confusion | `?redirect=\\evil.com` | High |
| CRLF injection | `?redirect=%0d%0aLocation:...` | Critical |

Same-origin bypass: URLs whose host is the request host or a subdomain are allowed (e.g., `?redirect=https://app.example.com/path` on `example.com`).

Attack corpus: 27/28 detected (96.4%). Tests: 15 unit cases + `FuzzOpenRedirectDetector` (16.7M fuzz executions, 0 crashes).

### GraphQL Depth/Complexity (`graphql-detector`)

Protects GraphQL endpoints from DoS via deeply nested queries, excessive aliasing, fragment cycles, and introspection.

| Metric | Default limit | Config key |
|---|---:|---|
| Max depth | 10 | `waf.graphql.max_depth` |
| Max complexity | 1000 | `waf.graphql.max_complexity` |
| Block introspection | true | `waf.graphql.block_introspection` |
| Allowed endpoints | `["/graphql"]` | `waf.graphql.allow_endpoints` |

**Attack vectors detected:** depth nesting, complexity (field count × depth), introspection (`__schema`, `__type`, `__typename`), aliasing abuse (>10 same-field aliases), fragment cycles (`fragment A {...B} fragment B {...A}`), batch-query bombs (multiple `query` keys in a single JSON request), and parenthesis-nesting attacks (`x:y(x:y(...))`).

**Transport formats supported:** raw `application/graphql`, JSON-wrapped (`{"query":"..."}`), and query parameter (`?query={...}`).

The parser strips string literals and comments before counting braces — a `}` inside a string like `description: "has a } char"` does not affect depth.

Attack corpus: 20/20 detected (100%). Tests: 18 unit cases + `FuzzGraphQLDetector` (13.5M fuzz executions, 0 crashes).

## SIEM Export (CEF over TLS Syslog)

Forward block and challenge events to external SIEM systems (Splunk, QRadar, Sentinel) via Common Event Format (CEF) over TLS syslog (RFC 5425, port 6514).

```yaml
waf:
  siem:
    enabled: true
    endpoint: "siem.example.com:6514"  # TLS syslog port (RFC 5425)
    format: "cef"                       # cef | json
    batch_size: 100                     # flush after N events
    flush_interval: "1s"                # or after this duration
    timeout: "10s"                      # per-write timeout
```

**Design properties:**

- **Asynchronous** — subscribes to the EventBus; network I/O never blocks request processing.
- **Batched** — events buffered and flushed every 100 events or 1 second (configurable).
- **Auto-reconnect** — exponential backoff on connection failure; dead connections detected and re-established.
- **Event filtering** — only `block` and `challenge` events are forwarded; `pass` events are silently dropped.
- **Tenant isolation** — events carry `tenant_id` for SIEM-side partitioning.

Dashboard integration: SIEM stats (events sent/dropped/reconnects) surfaced at `/api/v1/stats` under the `siem` key.

Tests: 14 cases covering CEF encoding, batching, timer flush, reconnection, TLS delivery, stats tracking, endpoint validation, and config conversion.

## WebSocket Inspection

WebSocket traffic previously bypassed all detection layers after the initial HTTP upgrade. An attacker could tunnel SQLi, XSS, or command injection through a WS connection undetected.

```yaml
waf:
  websocket:
    enabled: true
    scan_payloads: true                 # run detection pipeline on text frames
    max_frame_size: 1048576             # 1MB — reject oversized frames (DoS protection)
    allowed_origins:                    # CSWSH protection — block unknown origins
      - "https://app.example.com"
    max_concurrent_per_ip: 100          # prevent connection exhaustion
    block_binary_messages: false        # allow binary frames (size-checked only)
    idle_timeout: "60s"
```

**5 security controls:**

| Control | What it does |
|---|---|
| Origin validation | Blocks Cross-Site WebSocket Hijacking (CSWSH) |
| Payload scanning | Runs full 11-detector pipeline on text frames |
| Frame size limiting | Blocks oversized frames (DoS protection) |
| Binary blocking | Optionally block all binary frames |
| Connection limiting | Max concurrent WS connections per IP |

The layer is a middleware wrapper, not a pipeline layer — it intercepts HTTP upgrade requests and takes over the connection lifecycle. Binary frames are size-checked only (content inspection requires protocol awareness).

Tests: 20 cases covering frame parsing (RFC 6455), masking/unmasking, inspection, origin validation, connection limiting, and edge cases.

## Dashboard: Real-Time Event Tail (SSE)

The dashboard now shows live events via Server-Sent Events instead of polling every 5 seconds.

**New features:**

- **Live event feed** — events pushed in real-time via `GET /api/v1/sse` (auto-reconnect with exponential backoff).
- **Pause/Resume** — freeze the feed during incident analysis; buffered event count shown on the Resume button. Up to 500 events buffered while paused.
- **Connection status indicator** — green/red badge in the dashboard header shows live SSE state.
- **Filter chips** — All / Blocked / Challenged / Logged / Passed.
- **Search** — full-text search across IP, method, path, browser, OS.
- **Event detail** — click any row to expand findings (detector, severity, matched value, confidence, category).
- **Tenant isolation** — tenant-scoped API keys only receive their own tenant's events.

## Configuration Changes

### New config sections

- `waf.siem.*` — SIEM export (enabled, endpoint, format, batch_size, flush_interval, timeout, skip_verify)
- `waf.websocket.*` — WebSocket inspection (enabled, scan_payloads, max_frame_size, allowed_origins, max_concurrent_per_ip, block_binary_messages, idle_timeout)
- `waf.graphql.*` — GraphQL limits (max_depth, max_complexity, block_introspection, allow_endpoints)
- `waf.detection.detectors.smuggling` — smuggling detector toggle
- `waf.detection.detectors.openredirect` — open redirect detector toggle
- `waf.detection.detectors.graphql` — GraphQL detector toggle

### Removed from "removed layers" guard

`waf.graphql`, `waf.siem`, and `waf.websocket` were previously listed as unimplemented "removed layers" that errored when enabled. They are now fully implemented and enabled without error.

### Defaults

All new features default to **disabled**. Existing configs are unaffected — no behavior change unless the operator explicitly enables a new feature.

## Upgrading

1. **No breaking changes.** All new features are disabled by default.
2. To enable a new detector, add it to `waf.detection.detectors`:
   ```yaml
   waf:
     detection:
       detectors:
         smuggling: { enabled: true }
         openredirect: { enabled: true }
         graphql: { enabled: true }
   ```
3. To enable SIEM export or WebSocket inspection, see the config examples above.
4. Run `go test ./...` to verify — no existing tests changed.
