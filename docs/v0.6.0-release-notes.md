# GuardianWAF v0.6.0 — Distributed Clustering & Proven Hardening

**Release date:** 2026-09-12

This release closes the clustering goal from the v0.6.0 roadmap: a Raft-consensus control plane with SWIM gossip membership and a replicated state store for ban lists, rules, and counters — deployable on Kubernetes via shipped manifests, operable through six new `guardianwaf cluster` CLI commands, and observable through a Grafana dashboard. On top of that, 172 commits of detection/CRS hardening and more than 90 proven defect fixes from the proof-driven bug-hunt series (rounds 1–72) have landed.

## Distributed Clustering (Raft + SWIM Gossip)

### Consensus layer (`internal/cluster/raft`)

- Leader election with log replication; candidate self-votes are persisted so
  single-node commits cannot get stuck (`7e5d0d7`).
- Write-ahead log persistence for cluster restart survival (`e77c470`) with
  compaction/snapshotting for bounded log growth (`bb8aa6b`).
- Stale-term `RequestVote` rejection per Raft §5.2 and WAL snapshot
  `entryCount` bounding (`5df04a3`); startup election timeout bounded
  (`123f790`); WAL write-path size-accounting gap closed (`11ce920`).

### Membership & peer discovery (`internal/cluster/gossip`, `internal/peersync`)

- SWIM gossip membership protocol (`bd02f36`) integrated with Raft for dynamic
  peer discovery (`cc5001c`).
- Gossip and Raft peer traffic authenticated with HMAC-SHA256 (`5ad9206`).
- Protocol frame handling and relay path hardened (`a1c7162`); `EncodeMembers`
  writes address bytes correctly (`a79827a`); join/leave callbacks fire on
  transitions with `PurgeDead` wired into the probe cycle (`064dd04`); suspect
  timers are cancelled on Stop so `onLeave` cannot fire post-shutdown
  (`23c9cc3`); `UpdateMember` is guarded against use-after-shutdown
  (`1229eec`).

### Replicated state (`internal/clustersync`)

- Replicated state store for ban lists, rules, and counters (`4bf1878`), wired
  into the WAF request pipeline (`01d12dc`), with counter/ban lifecycle and
  ban-duration validation (`92ce3f3`).
- `ProposeBan`/`ProposeUnban` wired into the dashboard ban/unban handlers
  (`3b94fdb`); followers leader-redirect ban/unban requests (`bc68c94`).

### Dashboard & CLI surface

- Six cluster CLI subcommands: `status` (`839497f`), `health` (`5da5a8c`),
  `nodes` (`4eaa48c`), `bans` (`74337b1`), `ban`/`unban` (`938d5b6`).
- Cluster-aware readiness probe via gossip isolation detection (`a181ba0`);
  cluster Prometheus metrics (`c8513b7`); cluster health dashboard endpoints
  (`3900eb0`).
- Dashboard advertise address: a wildcard dashboard listen falls back to the
  Raft bind host so follower 307 leader-redirects stay routable (`e5ab53b`);
  `DashboardAddr` propagates via the gossip wire format (`6b53571`).

### Kubernetes & Grafana

- Cluster StatefulSet, headless Service, and PodDisruptionBudget manifests
  (`0b1bf3d`); Grafana dashboard with Raft and store metrics (`007d520`).

### Resilience testing

- 3-node integration tests for ban/rule/counter replication (`18d87ce`), ban
  propagation through dashboard handlers (`ee4630e`), a 3-node end-to-end
  flow — gossip → leader election → ban via follower → 307 redirect →
  replication (`ecf45a3`) — network partition / split-brain tests
  (`0a76cb5`), and chaos tests for leader failover during active ban
  operations (`2120bf7`).

## Detection & CRS Hardening

- Detector pattern hardening across cmdi, lfi, nosqli, sqli, ssrf, and xss,
  with openredirect and smuggling coverage (`5f1a71d`).
- CRS engine: from-file rules now read their argument files (`ac9f567`) —
  quoted/negated operators were previously inert for file-loaded rules
  (`b4dd220`); ARGS populated with quoted-operator recognition (`54915e0`);
  SETVAR increment and C3 regression (`05704bd`); strict `%`-escape
  validation, `&ARGS` counting, and Go `TIME*` layouts (`b81385d`).
- DLP: body replay scanning (`2c9977f`).
- Challenge: PoW difficulty validated at construction (`8401f33`); issuance
  and replay coverage (`f50ff44`).
- Engine: pipeline action escalation; response writer and redaction coverage
  (`ccfe536`).

## The Proof-Driven Bug-Hunt Series (90+ fixes)

Ninety-plus defect fixes landed through the proof-driven bug-hunt series
(every fix proven with a failing reproduction before the change). Highlights
by class:

**Request-path bypasses closed.** Rate limiting keys on the normalized path to
stop encoding bypass (`a9efecc`); the WebSocket layer always runs the origin
gate so empty `AllowedOrigins` denies browsers (CSWSH, `66f06cd`), forwards
takeover leftovers, and scans assembled continuation messages (`d31581d`) and
never dials a client-supplied Host for upgrades (`fe777fe`); CORS rejects the
all-origins wildcard combined with `AllowCredentials` (`56a45d3`) and
normalizes origins (`12deead`); clientside exclusions match on path boundary
(`e7e1fb8`); ATO builds /24 prefix keys in dotted decimal (`431a9b1`) and
records travel state on successful logins (`8fee0a7`); proxy multi-target
failover no longer starves healthy siblings under deterministic load-balancing
strategies (`64c6dfd`); Docker discovery selects networks and ports
deterministically (`e99cbce`, `f2e26e4`).

**CA & TLS lifecycle.** ACME `signedPost` preserves 400 problem documents
(`34671ee`); the renewal loop restarts with backoff after a panic
(`eb0c091`); force-renew inside the 30-day window with atomic cert/key
install and non-P-256 key rejection (`7e8585c`); certificate store lifecycle
hardening (`977669d`); OCSP response parsing, validity windows, and staple
policy (`d730578`).

**Honesty and lifecycle fixes.** Dashboard stub handler responses replaced
with real behavior and config mutations persisted with rollback (`bb1232c`);
compliance uptime/log-completeness metrics are no longer fabricated
(`4fc2087`); virtual patch DELETE disables honestly (`3ee6aec`); the Docker
events stream returns an error on death instead of hanging forever
(`2f2769d`); the AI analyzer backs off loop restarts after panic (`27f5b81`).

**Security plumbing.** API keys hashed at rest and JWT `kid` claims validated
(`2e530ed`); MCP sessions invalidated on API-key rotation (`5e5052d`);
v4-mapped IPv6 trusted-proxy CIDRs that degenerate to trust-everything are
rejected (`0a191e8`); regexsafe evaluates fail-closed with per-regex
deadlines (`fc3bfaf`).

## Upgrading

1. **No breaking commits** in the v0.5.0 → v0.6.0 range (verified by scan).
2. The Go toolchain is now 1.26.6 across all build paths.
3. Inert config structs `WAF.MLAnomaly` and `WAF.APIDiscovery` were removed
   and unknown `waf.*` keys are rejected strictly at populate time — remove
   them from your YAML before upgrading (`f9a0330`, `a51eab8`).
4. To enable clustering, configure the new `cluster` section and deploy the
   shipped Kubernetes manifests (`contrib/k8s/`) or review
   `examples/kubernetes/`.
5. Run `go test ./...` to verify — the full suite passes with `-race`.
